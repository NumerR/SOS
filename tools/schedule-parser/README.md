# Парсер расписания АПЭКС-ВУЗ

Папка — приложенный владельцем Python-парсер (`schedule_parser_background_only`):
`api_client.py` изменён, `README.md` переписан под этот договор, добавлены `groups.py`,
`fetch.py` и `test_contract.py`, остальное — байт в байт с архивом (`cmp`), а `scraper.py`
не перенесён (пункт 6 ниже). Сервер платформы вызывает `fetch.py` как
дочерний процесс; ничего здесь не работает «внутри» Go — граница ровно одна:
аргументы командной строки входят и одна строка JSON наружу.

## Что здесь за файл

| Файл | Откуда | Зачем |
|---|---|---|
| `api_client.py` | из архива, изменён | доступ к эндпоинту: HTTPS обязателен, токен только из `APEKS_TOKEN` или аргумента |
| `parser.py` | из архива, без изменений | разбор ответа в список пар (`ScheduleParser.parse_api`) |
| `renderer.py`, `colors.json`, `main.py` | из архива, без изменений | автономная HTML-страница расписания — платформой **не используется** |
| `groups.py` | новый | обход дерева групп вынесен из `api_client.py`, чтобы каталог разбирался без `requests` |
| `fetch.py` | новый | точка входа для Go-моста: JSON-вывод списком пар (и каталог групп) |
| `test_parser.py` | из архива | собственный тест разбора из приложенного файла |
| `test_contract.py` | новый | проверка договора `fetch.py` с Go-мостом по фикстурам живого ответа |
| `requirements.txt` | из архива | `requests` — нужен только сетевой ветке |
| `scraper.py` | из архива, **в репозитории его нет** | резервный сбор через headless-браузер (Playwright + Chromium); не перенесён — см. пункт 6 |

`main.py`/`renderer.py` оставлены как есть и никем не вызываются: страница `/schedule`
строит разметка платформы (`web/js/schedule.js`), а не этот скрипт, и переносить
второй рендер на тот же смысл — вторая копия вёрстки, расходящаяся с первой.

## Как это запускается из Go

`internal/apeks/python.go` собирает команду и исполняет её без оболочки:

```
python3 tools/schedule-parser/fetch.py --group-id 494 --month 10 --year 2026
python3 tools/schedule-parser/fetch.py --groups
```

Переменные окружения сервера:

| Переменная | Значение по умолчанию | Смысл |
|---|---|---|
| `APEKS_TOKEN` | — | токен источника; без него источник считается ненастроенным |
| `APEKS_API_URL` | `https://apeks.tksu.ru/api/call/schedule-schedule/student` | адрес эндпоинта, только HTTPS |
| `SCHEDULE_SOURCE` | `python` | `python` — этот парсер, `go` — нативный клиент `internal/apeks/client.go` |
| `SCHEDULE_PARSER` | `tools/schedule-parser/fetch.py` | путь к скрипту (в тестах — подставной) |
| `PYTHON_BIN` | `python3` | интерпретатор |

Токен передаётся **только окружением дочернего процесса**. В аргументах его нет:
командная строка видна в `ps` и попадает в логи падений, а переменные окружения
чужому процессу не видны. Коды выхода: `0` — данные на stdout, `1` — источник или
разбор не удались, `2` — неверный запуск. Всё, что не данные, пишется в stderr;
stdout — ровно одна строка JSON. Таймаут запуска — 20 секунд, stdout ограничен
8 МиБ, stderr — 4 КиБ.

## Договор вывода

Каталог групп:

```json
{"groups": [{"id": "494", "name": "Б-ИСиТ-22",
             "department": "Инженерно-технологический институт", "course": "2 курс"}]}
```

Месяц (поля `date`, `lesson_number`, `time`, `group`, `subgroup`, `discipline`,
`lesson_type`, `room`, `teacher` читаются Go-мостом как есть):

```json
{"group_id": "494", "group_name": "Б-ИСиТ-22", "start_date": "2026-09-01",
 "end_date": "2026-10-31", "lessons": [{"date": "02.10.2026", "room": "к. 2/102",
  "external_id": "py:e9d3f9694abd2ac5", "...": "..."}]}
```

`external_id` считается из содержимого строки (`sha1`, 16 hex, префикс `py:`) и
нужен только для дедупликации: повторный импорт того же месяца обновляет те же
строки, а не плодит копии. В `parser.py` id пары у источника не сохраняется,
поэтому детерминированный хеш считается здесь.

HTML в полях источника (`<i class="fa fa-times"></i> без ауд.`) парсер не трогает —
он отдаёт то, что пришёл. Вырезает разметку Go-мост (`stripHTML`), и только перед
записью в базу: страница вставляет текст как `textContent`, и разметка источника
не может стать элементом DOM.

## Запуск руками

```bash
# с network — нужен токен вуза и requests
APEKS_TOKEN=<токен> python3 fetch.py --groups
APEKS_TOKEN=<токен> python3 fetch.py --group-id 494 --month 10 --year 2026

# офлайн — по срезу живого ответа, без токена и без requests
python3 fetch.py --groups --from-file ../../internal/apeks/testdata/apeks-groups-tree.json
python3 fetch.py --from-file ../../internal/apeks/testdata/apeks-2026-10-week.json --group-id 494
```

## Проверки

```bash
python3 -m py_compile tools/schedule-parser/*.py   # синтаксис всех модулей
python3 tools/schedule-parser/test_parser.py       # тест из приложенного архива
python3 tools/schedule-parser/test_contract.py     # договор CLI с Go-мостом
go test ./internal/apeks -run TestPythonGroupsMatchGoParser -v
```

Последняя — паритет: каталог с фикстуры разбирают python и Go, результаты
сравниваются поэлементно (Go идёт по map, поэтому сортировка по id перед сравнением
обязательна). Тест пропускается, если `python3` не найден, поэтому в job `go`
интерпретатор ставится явно — иначе «зелёный» CI означал бы «пропущено», а не
«совпадает». Все четыре проверки — офлайн: живое API из проверок не дёргается.

## Что здесь изменено против архива владельца

1. **Зашитого токена нет.** В приложенном `api_client.py` был `DEFAULT_TOKEN` прямо
   в коде; секрет в репозитории пережил бы любой срок жизни токена и попал бы в
   историю git. Доступ берётся только из `APEKS_TOKEN` (или аргумента).
2. **Схема закреплена за HTTPS.** Токен едет в строке запроса, поэтому открытый
   `http` отклоняется при конструировании клиента, а не первым запросом.
3. **`fetch.py` вместо прямого вызова CLI**: вывод списком пар в JSON, коды выхода,
   `--from-file` для офлайновых проверок, `--groups` для каталога.
4. **`groups.py`**: обход дерева групп вынесен из `api_client.py`, чтобы `--groups`
   можно было запустить без установленных пакетов.
5. **`test_contract.py`** — его в архиве не было.
6. **`scraper.py` не перенесён.** В архиве он открывает страницу виджета в
   headless-браузере (Playwright + Chromium) и забирает уже отрисованную разметку —
   резервный путь добычи там, где платформе достаточно обращений к тому же API.
   Зависимость, которая не запускается ни в CI, ни на хостинге и не проверяется офлайном,
   в продуктовый код не добавлялась; при необходимости это отдельное решение (ADR-0021,
   «что это не закрыло»).
7. **Остальное — байт в байт.** `parser.py`, `main.py`, `renderer.py`, `test_parser.py`,
   `colors.json` и `requirements.txt` сверены с архивом через `cmp` и не менялись:
   разбор формата по-прежнему живёт в коде вуза, а не в нашей правке на глаз.
